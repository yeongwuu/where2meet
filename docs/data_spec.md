## 3. 파일별 필드

### 3-1. `members.json`: 같이 갈 사람

팀 구성 규칙 (전 팀 같음)
- 팀: Assurance 1~8팀, Tax 1~3팀, Deals 1~3팀. 팀마다 8~9명
- 팀마다 파트너(임원) 1명, 상사(매니저·디렉터) 2명, 취향 미입력 1명
- 알레르기는 취향 입력한 사람의 약 16%, 채식·할랄은 약 8%. 술·분위기는 팀마다 성향이 조금씩 달라요
- 닉네임은 순우리말 두 글자, 전원 겹치지 않음
- 처음 12명(`p01`~`p12`)은 처음 데이터 그대로예요. 하늘(체험 계정)은 Assurance 3팀이고, 하랑·한결·누리만 2·4·5팀으로 소속을 옮겼어요

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | `p01` 형식 |
| `nickname` | string | 화면에 보이는 이름. 실명 대신 닉네임 |
| `team` | string | 팀 이름. ② 팀 그룹으로 묶을 때 써요 |
| `rank` | `rank_*` | 직급. 상사·임원 배지를 정해요 (아래 3-5) |
| `is_member` | boolean | `false`면 아직 취향을 입력하지 않은 사람. 화면에서는 "취향 모름"/"미입력" |
| `allergies` | `allergy_*`[] | 못 먹는 것 (알레르기) |
| `diet` | `diet_*`[] | 못 먹는 것 (식단) |
| `likes` | `food_*`[] | 좋아하는 음식 |
| `dislikes` | `food_*`[] | 별로인 음식 (`likes`와 겹치지 않음). 샘플은 0~2개, 채식은 고기구이 · 생선·갑각류·조개 알레르기는 해산물을 먼저 넣었어요. 미입력이면 `[]` |
| `drink` | `drink_*` \| null | 술. 미입력이면 `null` |
| `mood` | `mood_*` \| null | 분위기. 미입력이면 `null` |

| `name` | string | 식당 이름 |
| `food` | `food_*`[] | 음식 종류 (썸네일의 업종명) |

### 3-3. `guests.json`: 비회원
② 비회원 목록, ⑤ 비회원 메모 카드에서 써요. ②에서는 평소에 고른 비회원만 보이고, 검색(호칭·회사·부서)으로 찾아서 더해요. 메모·취향은 아직 비어 있어요.

②의 "+ 비회원 추가"로 만든 비회원은 파일이 아니라 브라우저(`w2m.guests`)에 저장돼요. id는 `gm` + 숫자, `mine: true`가 붙어요. 관계가 거래처면 `group`은 고객사, 나머지는 사내예요.

구성
- `g01`~`g03`: 목업의 3명 (재무본부 상무님, A사 재무팀장님, 감사본부 파트너님)
- 사내 백오피스 24명: 회계팀·재무팀·인사팀·교육팀·총무팀·IT지원팀·법무팀·홍보팀 × 팀장님·과장님·대리님
- 고객사 77명: A사~Z사 × CFO님·재무팀장님·회계부장님 (A사 재무팀장님은 `g02`)

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | `g01` 형식 |
| `title` | string | 호칭 (예: "A사 CFO님"). 실명 쓰지 않음 |
| `org` | string | 회사 또는 부서 (예: "A사", "인사팀") |
| `group` | `사내` \| `고객사` | 구분 |
| `relation` | string | 관계 배지: `임원` / `상사` / `거래처` / `사내` (백오피스 직원) |
| `allergies` | `allergy_*`[] | 아는 범위의 못 먹는 것 |
| `diet` | `diet_*`[] | |
| `likes` | `food_*`[] | 좋아함 |
| `dislikes` | `food_*`[] | 별로 |
| `needs` | string[] | 꼭 필요 (예: "룸", "주차") |
| `memo` | string | 메모 본문. 나만 보기 |
| `history` | `{date, text, from_review_id}`[] | 기록 줄. 후기를 올리면 여기에 추가돼요 |

### 3-5. 상사·임원 배지
| 대상 | 기준 |
|---|---|
| 회원 | `rank_partner` → 임원 · `rank_manager`, `rank_director` → 상사 · 나머지는 배지 없음 |
| 비회원 | `relation` 값을 그대로 (`임원` / `상사` / `거래처`) |
| 나 | 배지 없음, 인원 요약의 임원·상사 수에서도 빠져요 |

### 3-6. 모임 (브라우저에 저장, 파일 없음)
② 모임 만들기에서 만들어 ③ 이후 화면으로 넘겨요. 저장 키는 `w2m.meeting`이에요. (내 프로필은 `w2m.profile`, ②에서 내가 추가한 비회원은 `w2m.guests`)

②에서 취향 미입력 배지를 눌러 입력을 부탁하면 `w2m.requests`에 `{ 회원 id: 부탁한 시각 }`으로 저장되고 배지가 "요청함"으로 바뀌어요. 지금은 서버가 없어서 실제 알림은 가지 않아요.

| 필드 | 타입 | 설명 |
|---|---|---|
| `people` | string[] | 고른 사람 id. 회원 `p*`, 비회원 `g*`, 나 포함 |
| `purpose` | `purpose_team` \| `purpose_farewell` \| `purpose_client` | 팀 회식 / 환영·송별 / 접대 |
| `budget` | [number, number] | 1인 예산 [최소, 최대] 원. 최대 `100000`은 "10만원 이상" |
| `day` | `day_today` \| `day_tomorrow` \| `day_pick` | 오늘 / 내일 / 날짜 선택 |
| `date` | string | `day_pick`일 때 `YYYY-MM-DD` |
| `time` | string | 시간 `HH:MM`. 점심 11:30~13:00, 저녁 17:00~20:00 중에서 골라요 (기본 18:30) |
| `team` | string | 소속 팀. 이 팀 사람이 처음에 모두 체크돼요 |
| `place` | `place_*` | 회사 / 신용산역 / 용산역 / 삼각지역 |
| `walk` | `walk_5` \| `walk_10` \| `walk_15` | 도보 시간 |
| `apply` | `{character, food, drink}` (boolean) | ③ 스위치로 추천 반영 여부. 없으면 모두 `true`. 끈 항목은 ④ 점수에서 빼요 |
| `updatedAt` | string | 마지막 수정 시각 |

## 4. 추천 로직
②에서 고른 사람과 모임 정보 → ③ 취향 종합 → ④ 추천 3곳 순서로 계산해요.

### 4-1. 취향 종합 (③)
- **취향 입력한 사람**: `is_member: true`인 사람만 집계해요. 나머지는 "취향 모름 n명"으로 따로 보여 줘요.
- **반드시 피할 것**: 고른 사람 전체의 `allergies`, `diet`를 합쳐요. 이름 없이 "갑각류 1명"처럼 인원만 보여 줘요. 스위치로 끌 수 없어요.
- **다 같이 좋아하는 음식**: `food_*`마다 `likes`에 들어 있는 사람 수를 세어 많은 순으로 막대를 그려요.
- **술·분위기**: `drink`, `mood` 비율을 막대로 보여 주고, 가장 많은 값으로 결론 한 줄을 만들어요. (예: "반주 정도의 식사 중심", "조용한 곳에서 반주 정도의 식사 중심")
  - 술: `drink_none` → 술 없이 식사 중심 · `drink_light` → 반주 정도의 식사 중심 · `drink_enjoy` → 술자리 중심. 같은 수면 덜 마시는 쪽
  - 분위기: `mood_quiet`·`mood_lively`가 가장 많으면 "조용한 곳에서 / 활기찬 곳에서"를 앞에 붙여요. `mood_any`가 가장 많거나 같은 수가 있으면 붙이지 않아요 (중립)

### 4-2. 조건 거르기 (꼭 지켜야 하는 것)
아래 중 하나라도 어기면 추천에서 빼요.
1. 식당 `allergens`와 고른 사람들의 `allergies`가 하나라도 겹침
2. 고른 사람 중 `diet`가 있는데 식당 `diet_ok`에 그 식단이 없음
3. `capacity` < 인원
4. `price_per_person`이 예산 범위를 벗어남

남은 식당 수를 ④ "조건을 지키는 곳 n곳"에 보여 줘요.

### 4-3. 점수 (순위 정하기)
남은 식당마다 점수를 매겨 높은 순으로 3곳을 보여 줘요. ③에서 스위치를 끈 항목은 점수에서 빼요.

| 항목 | 계산 | 화면 근거 |
|---|---|---|
| 음식 | 식당 `food`를 좋아하는 사람 수 ÷ 취향 입력한 사람 수 | ✓ "10명 중 7명이 좋아하는 음식" |
| 술 | 식당 `drink`가 결론과 같으면 가점 | ✓ "반주 정도에 맞아요" |
| 분위기 | `mood_any`는 중립, 결론과 같으면 가점, 반대면 감점 | ✓ / ⚠ |
| 룸 | 상사·임원 동석이면 `private_room: true`에 가점 | ✓ "룸 있음" / ⚠ "룸 없음" |

> 가중치(음식 50 · 술 20 · 분위기 15 · 룸 15 등)는 구현하면서 정하고 이 표에 적어 주세요.

### 4-4. 근거 문장 (④ 카드)
- ✓ 맞춘 조건: 점수를 얻은 항목을 문장으로
- ⚠ 확인할 점: 감점 항목, 취향 모름 인원, "알레르기는 예약할 때 한 번 더 확인해 주세요"

## 5. 아직 정하지 않은 것
- 식당의 영업시간·주차·확인일(④ 펼친 카드)과 위치 필드가 없어요. ②의 "어디서"(회사·역, 도보 시간)로 거르려면 식당마다 가까운 역과 도보 시간이 필요해요.
